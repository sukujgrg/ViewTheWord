# Native AppKit workspace — September 9, 2026

Each passage workspace uses a native AppKit controller hierarchy. This removes the SwiftUI navigation/list/focus bridges involved in the unresolved first-chapter-click report. The design uses native toolbar controls, split panes, selection, and text fields.

## Interface

- Passage tabs use AppKit window tabbing. Each tab contains the complete book → chapter → verse workspace and keeps its native controls, draft, search mode/results/selection, and scroll state. Titles follow the prepared passage (for example John 3, Psalm 23, Romans 8); text searches show Search with the query in the tab tooltip.
- Command-T opens a blank tab. Command-Return opens the selected passage in a new tab. Book, chapter, verse, search-result, bookmark, and history context menus also offer Open in New Tab. Preparation never projects or records history. Command-W closes a tab; Command-Shift-W closes its group; Control-Tab/Control-Shift-Tab or Command-Shift-[/] switch tabs. Drag tabs to reorder; Window commands also move, detach, merge, and show all tabs.
- Books use a native outline sidebar with Old and New Testament groups.
- Chapters use an `NSCollectionView` of number-only buttons. The grid computes its column count from available width and fills the row evenly. Native arrow navigation follows the current arrangement.
- Bookmarks and History have separate resizable panes, dedicated reference rows, empty states, and action menus. Activating an entry loads, selects, and projects its verse in one action. History remains grouped by week; replaying an entry does not record it again.
- Verse rows and search results share the native reference table. Result headings show coordinates and translation matches. Keyboard result selection remains separate from projection activation.
- Search is a real `NSSearchToolbarItem`, accompanied by the Ref/Words/Phrase segmented control. Native control metrics determine text and icon alignment.
- Translation pickers sit directly above their respective verse columns, with the book and chapter centered between them on the same row. The projection status and Preview/Blank/Stop row sits above that heading. Display selection and presentation options are also native controls. Standard menu and responder commands include editing, bookmark Undo/Redo, search focus, sidebar toggling, settings, and help.

## Ownership

`ViewTheWordApp` starts `NSApplication`. `AppDelegate` retains `PassageTabsController`, which retains every `MainWindowController` including hidden or detached tabs. Each passage controller owns one window and one `MainWorkspaceController` with an independent `VerseTargetModel`. Native tab groups are the source of truth for ordering and selection; switching tabs does not rebuild controls or submit navigation/projection. Snapshots update native controls silently. Explicit navigation may focus controls only in the key passage window.

Bookmarks, History, bookmark Undo, BibleLibrary, preferences, and `LiveProjectionController` are shared. The shared live controller alone calls `ProjectorViewModel.project`/`clearProjection` and owns exactly one projector `NSWindow`. Every tab observes its live reference, blank state, and pending projection status; Preview hosts the same model locally. Closing even the last passage window leaves published output alive; reopening from the Dock restores access to its controls. Application termination stops output.

A projection intent reserves a global generation before asynchronous navigation/search-result preparation starts. A newer intent or Stop from any tab cancels the prior preparing model's projection generation without canceling chapter browsing. Per-tab navigation cancellation still suppresses its own pending submission. Shared translation refresh uses a dedicated reader, preserves the live reference and blanking, and survives browsing or originating-tab closure. Unavailable live references stop output.

Deferred close cleanup preserves both projection revision and window identity guards. It clears the closed output without clearing a newer pending request's status; new publication or a reopened/replacement window survives stale cleanup. Screen changes use one cancellable, coalesced reposition task. The projector remains an owned `NSWindow`, with no projector `NSWindowController`. Settings, help, preview, and projected content remain separate hosted SwiftUI screens, explicitly excluded from passage tab groups. No SwiftUI representables appear inside a workspace.

## Validation and review

- Build with `xcodebuild -project ViewTheWord.xcodeproj -scheme ViewTheWord -configuration Debug -derivedDataPath build/DerivedData CODE_SIGNING_ALLOWED=NO build`.
- Run `swift test --scratch-path build/SwiftPM -Xswiftc -strict-concurrency=complete` and `python3 scripts/test-review-regressions.py`.
- Run `scripts/render-navigation-review.sh` for the AppKit window-event regression and adaptive-layout fixtures. It launches a local test application through LaunchServices with an injected fixture translation catalog, then requires a running AppKit application and real key window; it does not mock key-window state or call a table's mouse handler directly.
- Run `scripts/render-projector-review.sh` for projected-output wrapping and fitting.

The window-event harness covers the first book-to-chapter click for four books, spatial grid arrows, toolbar search command routing, adaptive widths, and chapter reveal. Populated, scrolling Bookmarks and History fixtures verify that rows fill their panes and retain the same leading alignment at each width. The tab event checks exercise new/close/reorder commands, preparation through context menus and Command-Return, independent draft/caret/viewport/search state, cross-tab verse and saved activation, shared live/Blank/Preview/Stop controls, closing the originating tab, and window-dispatched Escape while a different tab’s search-result or verse request is deliberately suspended. Projector window creation is suppressed; a counted factory verifies one logical output lifetime across tabs. A unit fixture also verifies actual owned `NSWindow` reuse, Stop/reopen, and rejection of stale close notifications without displaying output. Unit tests use a database that deliberately returns canceled work to verify global supersession, cancellation, Stop from another workspace, translation refresh after origin closure, unavailable live verses, and deferred cleanup alongside newer requests. The suite also checks that tabs share their bookmark UndoManager and covers window responder Undo, editing/caret preservation, and search activation.

Physical OS-delivered clicks and keyboard events, VoiceOver, Finder imports, HDMI reconnect, and Spaces remain manual checks. Computer-use permissions were unavailable during the original migration; this tab implementation used synthetic events. Offscreen view caching does not fully capture macOS glass, including the toolbar, selected tab, and floating book-sidebar surface, so the actual built app is the visual review target. See [manual validation](manual-validation.md).

The passage-tab implementation passed 62 Swift tests with complete concurrency checking, all three Python regressions, the native tab/event/viewport/cancellation fixtures, and the five projector rendering fixtures. Debug build and the current-architecture Release archive/export were also validated. These event checks use synthetic window-dispatched input and native menu key equivalents; they do not establish physical input, VoiceOver, HDMI, or Spaces behavior.
