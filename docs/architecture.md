# Architecture

ViewTheWord uses native AppKit controls for passage preparation and one shared committed scripture projection feeding independent outputs. Settings uses native AppKit toolbar panes and controls. Help, preview, and projected content are separate hosted SwiftUI screens, excluded from passage tab groups.

## Application and state ownership

[ViewTheWordApp](../ViewTheWord/ViewTheWordApp.swift) starts `NSApplication`. `AppDelegate` retains `PassageTabsController` and the application updater. Passage windows can close independently of live output; reopening from the Dock restores access to its controls. Application termination shuts down output.

| Component | Responsibility |
| --- | --- |
| [PassageTabsController and MainWindowController](../ViewTheWord/AppKit/MainWindowController.swift) | The tab controller retains passage windows, including hidden and detached tabs, and provides shared projection, saved-reference stores, bookmark Undo, and update controls. Each window controller owns one workspace. |
| [MainWorkspaceController](../ViewTheWord/AppKit/MainWorkspaceController.swift) | Own each tab's identity, translation choices, native controls, query draft/mode/selection, testament filter, and navigation orchestration. |
| [VerseTargetModel](../ViewTheWord/Core/VerseTargetModel.swift) | Own a tab's navigation snapshot, search results, lazy readers, and cancellable preparation. Prepare projection data without opening windows or publishing live content. |
| [LiveProjectionController](../ViewTheWord/AppKit/WorkspaceProjection.swift) | Order projection intents across tabs, publish through `ProjectorViewModel`, and own all native output `NSWindow` instances directly and independent AltView sender sessions. |
| [BibleLibrary](../ViewTheWord/Core/BibleLibrary.swift) and [persistence stores](../ViewTheWord/Core/Persistence.swift) | Share translations, bookmarks, history, and recovery/error state across workspaces. |
| [SettingsWindowController](../ViewTheWord/AppKit/SettingsWindowController.swift) | Own native Manage Outputs and Bible Library toolbar panes and import/removal sheets across both panes. Closing Settings declines unresolved replacement decisions, including validation still in flight. |

Native tab groups own tab ordering and selection. Switching tabs preserves each workspace's controls, navigation, draft, results, caret, scroll positions, and `PassageTranslations` value. Each tab has Primary and Secondary pickers; Secondary includes None for one translation. The internal `primaryOnly` flag and retained secondary URL preserve compatibility with saved preferences. Preferred URLs survive catalog fallbacks and are resolved by filename into the available `BibleSources` for each operation. Rendering never writes preferences. Explicit translation changes save the last selection for the next first passage, without changing existing tabs. New tabs and windows copy the originating or selected tab's choices once. Settings contains Manage Outputs and Bible Library management. Output profiles contain appearance; Bible choices remain in passage tabs. Native sliders update their point readouts during tracking and save a whole-point `Double` on mouse-up; keyboard and accessibility actions save immediately. Library sheets belong to the window, including the file picker and removal confirmation. The library retains security-scoped access for every selected import URL. Bookmarks, History, bookmark Undo, the translation catalog, appearance/output preferences, and live output are shared. Preview is local to a tab and observes the shared projector model.

Native tab titles include the browsed passage and short translation names; tooltips contain the full names and search query. Search headings and tooltips use the same available search page as the table, so pending or failed searches keep the heading of the visible passage. The retained search request remains available for retry after a translation change. The source tab's attributed title starts with an 8-point green image attachment followed by native `Live` text. The non-template `NSImage` draws a circle with `NSColor.systemGreen` at the requested scale and appearance; its color stays visible when another tab is selected, whereas AppKit dims foreground colors applied to title text. Blanked output uses a muted `● Blanked` text marker. Status remains readable text in the attributed title, plain title, and tooltip for accessibility. Native selection styling stays intact. The title follows browsing while the shared footer continues to describe the actual projected verse.

## Navigation and native controls

`VerseTargetModel.verseQuery` is derived from one published navigation snapshot containing the selected reference, complete chapter rows, and translation sources. Controls emit complete `VerseReference` intents. Chapter navigation uses those references directly, and verse-row projection validates that the reference exists in the loaded chapter. Verse numbers can differ between translations; row positions are not verse identities.

Snapshots update controls silently. Only explicit navigation may request focus, and only in the key passage window. Asynchronous completion also checks that the user has not changed the draft, editing session, or focus since submission; AppKit's normal Return handoff is part of that submission. Library prompts claim a shared alert before presenting so multiple tabs cannot show it at once; dismissal completes that alert by ID.

Navigation and search completions return `Result` after the current request settles. Empty chapters and database failures report failure; a missing verse with an available chapter fallback reports success with `requestedAvailable = false`. Canceled or superseded requests do not call back. Failed submissions retain the draft and focus, and never record history or publish output.

- [Book, bookmark, and history sidebars](../ViewTheWord/AppKit/NativeSidebar.swift) use native rows. The pinned Old Testament / New Testament switch filters visible books independently in each tab; explicit reference navigation reveals the matching testament, while translation and catalog refreshes preserve the filter and browsed book. Bookmarks and History have separate resizable panes.
- The [chapter grid](../ViewTheWord/AppKit/ChapterGridController.swift) adapts its column count to the available width. Arrow keys follow the spatial layout. After browsing a new book, Tab changes focus without navigating; the first arrow, Return, or Space opens chapter 1. Command-Left/Right moves between workspace columns.
- [Verse and search-result tables](../ViewTheWord/NativeReferenceTable.swift) use automatic row heights from constrained text fields. Resize-driven height updates are coalesced after layout. Bookmark refreshes preserve the viewport; search pagination inserts rows while retaining existing heights and the visible reference plus offset. Explicit navigation and saved-reference activation wait for measured row heights, then center the verse or show its beginning if taller than the viewport. New navigation or user scrolling cancels the previous reveal. Scroll tests synchronize on reveal completion before changing the viewport. Tab/Shift-Tab use AppKit's normal focus traversal.
- A real `NSSearchToolbarItem` hosts the [native search field](../ViewTheWord/NativeSearchField.swift). Editing preserves the draft until submission, and recent queries are separate for Ref, Words, and Phrase modes. Escape stops projection while preserving the draft.

Book/chapter browsing and Open in New Tab prepare a passage without projecting or capturing history. Ordinary verse selection projects. Search-result arrows only select; Return, Space, or a click activates projection. Search selection changes are accepted only while the results match the tab's current sources, including its catalog revision. Bookmark and History activation loads, selects, and projects the reference, including reactivating the same row. Space stops output only when the selected reference and the tab's translation sources match live output; otherwise it projects that tab's selection. Space requires an enabled row selection; use Stop or Escape to stop frozen output when the catalog is empty.

## Live projection and window lifecycle

The shared live controller is the sole publisher through `ProjectorViewModel.project(_:owner:)` and `clearProjection()`. Typed `ProjectionOwner` values distinguish direct reference submissions, verse selections, and search results. `ProjectionSource` records the supplying tab ID and the exact `BibleSources` snapshot used to prepare output; ownership transfers only on successful publication. Every passage observes the same Live, Blank, and pending-projection state.

A projection intent reserves a global generation and source snapshot before asynchronous preparation begins. Success, failure, and an explicit model cancellation callback settle that intent; rendering and preference refresh never infer completion from `isProjecting`. Cancellation callbacks are cleared before invocation and before successful completion, and are scoped to the live intent token. A newer projection intent or Stop from any tab invalidates older preparation without canceling chapter browsing. Each navigation model also cancels its own superseded verse submission. Changing a tab's sources invalidates only that tab's pending preparation. Translation changes in the tab supplying output refresh the live reference using a dedicated shared reader, preserving blanking. Such a refresh waits behind another tab's explicit pending projection, then runs only if the original tab still supplies output. An unavailable live reference stops output.

Closing the source tab detaches its identity without clearing published content. A translation refresh already requested before closing can finish using its captured sources, independent of the closed tab's navigation. Afterward, output remains frozen until another projection or Stop. Library revisions resolve each open tab's preferred choices and refresh its rows; only the source tab can refresh live translations. Missing-translation fallbacks come from the shared catalog, independently of saved defaults. Re-importing a preferred filename restores it unless the user explicitly chose another translation. The pickers show the effective translation and explain fallbacks in their tooltips.

An empty catalog returns no `BibleSources`; preferred URLs may also be absent when no choice has ever been available. The workspace disables translation pickers, clears visible rows, and explains how to import a Bible. Navigation, search, and projection do not create readers without sources. Empty-catalog refresh stops output owned by an open tab with a shared explanation. Restoring the catalog resumes browsing and clears that notice without automatically reopening stopped output. The live controller observes catalog availability independently of passage tabs, so recovery also clears the notice after every tab closes. No fake database URL or `/dev/null` placeholder is used.

Projection errors belong to the shared live controller and can be dismissed from any tab's footer. Explicit Stop clears the error; automatic stopping after an unavailable translation preserves the explanation until dismissal or another projection intent. Empty-catalog notices and projection failures have distinct types; catalog recovery clears only the empty-catalog notice and preserves unrelated failures.

The live controller owns every native window directly, without a projector `NSWindowController`. Its dictionary records destination ID, window instance, assigned monitor and an observable appearance model. All windows observe the same `ProjectorViewModel`; profiles filter that committed snapshot without database access. Closing the last passage tab leaves published output running. Each explicit intent authorizes native openings by destination ID; a destination close/loss revokes only its opening permission. Other ready destinations keep pending preparation, and reconnect cannot revive the closed destination through an older intent. Remote failures never cancel preparation for a native destination. A native close or monitor loss removes only its destination, unlocks its monitor and updates sleep protection synchronously. If it was the final live destination, payload cleanup is deferred and guarded by the committed revision; a newer publication or pending intent survives. Stop cancels preparation and remote requests, closes normal native windows and leaves an already-open Confidence window showing its empty-state clock. Projector Escape defers closing that particular window to the next run-loop tick.

Screen changes use a cancellable, coalesced reposition task for each open window's saved display UUID. Unavailable assignments remain saved, close only their output without fallback, and require explicit reopening after reconnect. Windows use the monitor's full `frame`, borderless frame constraints, `.screenSaver` level and hosting edges with ignored safe areas, including the menu bar and Dock regions. Explicit publication raises windows while preserving the operator's key window; background refresh never raises them. [Projected text layout](../ViewTheWord/Core/ProjectorTextLayout.swift) measures the selected font family and weight in AppKit, followed by SwiftUI natural-height checks without a fixed line-count cap.

## Output profiles and Manage Outputs

[OutputConfigurationStore](../ViewTheWord/Core/OutputConfiguration.swift) owns one versioned document in defaults. Reusable `NativeOutputProfile` values own verse, reference and translation-name typography; component colours; padding; alignment; reading direction; horizontal/vertical translation layout; component visibility; placement; transparency/background and empty/blank behavior. Destinations own their name, enabled state and either a native monitor/profile assignment or an AltView receiver/layout assignment. Audience migrates the former appearance and monitor choice. Confidence starts with both translations, reference and names and shows a centered clock when empty or blanked. Lower Third starts with primary scripture in the lower 30 percent on chroma green. Duplicating a profile creates an independent ID. Missing secondary text and its name consume no layout space; missing-primary fallback remains prepared once in `PreparedProjection`.

Migration reads former projector styling keys, the UUID assignment (or a uniquely connected legacy runtime ID), and the saved AltView receiver/layout once. The former accent/teal colours resolve under the projector's dark appearance, independently of the operator's appearance. Only the migrated native Audience destination is initially enabled among native outputs; an existing remote connection remains configured for restoration. Legacy keys have no render/editor bindings after migration. Unreadable and future documents remain untouched and disable editing/output; Restore Defaults retains the original value under a unique recovery key before writing the current format.

[ManageOutputsController](../ViewTheWord/AppKit/ManageOutputsController.swift) is the sole native destination editor, reached from Settings and Projection → Manage Outputs. Its Outputs and Profiles lists expose assignments, reusable profile editing and duplication. Native monitor choices include None, connected and remembered unavailable assignments, Identify and Name. Active assignments are locked per destination. Enabled outputs cannot share a usable physical monitor or an AltView receiver. Disabled and missing assignments do not reserve monitors or receiver ownership; receiver availability comes from shared discovery and connected sessions. Native conflicts that become usable after reconnect block both until resolved; authenticated receiver aliases are rejected before taking output. Receiver checks use account and advertised/authenticated UUID identity, including manual-address aliases, before any ownership request. AltView rows embed connection and advertised-layout controls without native styling. The old Display, Monitors and AltView panes and toolbar presentation editors are removed. Browsing row size and application appearance remain workspace preferences.

`ProjectorView` renders committed scripture plus a supplied profile, without defaults bindings or publication actions. Native preview observes the same committed model and chosen output's profile/proportions. Clock standby is intentionally available to every native profile; Confidence enables it by default, while Audience and Lower Third opt in. App launch opens enabled, assigned native clock outputs without requiring scripture; explicitly enabling, assigning or choosing a clock profile in Manage Outputs can also open standby while empty or blanked. The native “Show clock when empty or blanked” checkbox edits the selected profile's single persisted standby setting, shared with its profile editor. Turning it off closes standalone clock windows, while retaining committed or blanked scripture windows. A pending explicit verse retains its destination until preparation settles, so changing the clock setting cannot revoke that projection. Standby cannot change scripture, claim a source tab or submit to AltView. There is no separate Show Standby Clock action. Passive settings/discovery updates and monitor reconnection never reopen clocks; explicitly re-enable the destination, turn its profile's clock checkbox off/on, or project a fresh passage to reopen a manually closed or disconnected destination.

Manage Outputs tracks an explicit empty detail state when the last destination is removed. Destination name drafts retain their originating ID, and selection changes finish the native field editor before reusing its control; late editing notifications cannot rename a different destination. Invalid profile names show a validation message and restore the saved name instead of appearing to save an invalid value.

## Bible data and persistence

The injectable `BibleReading` interface separates navigation from SQLite. [Database readers](../ViewTheWord/Db.swift) open lazily and keep all SQLite access on their private queues. Queries select named columns and identify verses by coordinates, independently of an imported `id` or column order.

Text search merges coordinates from both selected translations, fetches counterpart text, and uses cursor pagination with a lookahead. The [query parser](../ViewTheWord/RxVerse.swift) validates references and Words expressions; whole-word matching uses Unicode boundaries, while Phrase searches escape literal wildcard characters.

The shared library publishes catalog revisions after import, replacement, or removal. Imports queue incoming URLs and retain security-scoped access until completion or a replacement decision. Each import snapshots committed SQLite/WAL data, normalizes the copy, validates canonical coverage and coordinates, creates a unique index, and installs atomically. Replacement requires an explicit choice; cancellation or failure advances the queue, and results retain their original presenter. Removal uses Trash. See [Bible translation format](bible-format.md).

History capture is limited to direct reference submissions; replaying saved entries does not capture history. Bookmark changes use a shared UndoManager. Both stores preserve unreadable data as recovery copies and report persistence errors visibly. Successfully decoded files with invalid references are backed up and rewritten with valid, normalized entries, so reopening does not produce another recovery copy. A failed backup still disables saving to protect the original.

## Updates and validation

One [AppUpdateController](../ViewTheWord/AppKit/AppUpdateController.swift) belongs to `AppDelegate` and is shared across passage toolbars. [SparkleUpdateDriver](../ViewTheWord/SparkleUpdateDriver.swift) owns the native update UI and installer integration; scheduled reminders preserve focus and projection, and installation requires user action. See [self-updates and release signing](self-updates.md).

The [build and test commands](../README.md#build-and-test) exercise the core, native controls, persistence, and shared projection. Tests inject readers that return canceled work to verify supersession and deferred cleanup; updater tests use an injected driver without network checks or installation.

The [navigation harness](../scripts/render-navigation-review.sh) launches a fixture app through LaunchServices with an injected translation catalog and a real AppKit event loop. It dispatches synthetic input through a key window to check tab state, navigation, focus, layout, and projection intent handling while suppressing projector windows. The [projector renderer](../scripts/render-projector-review.sh) checks output wrapping and fitting offscreen. Physical input, VoiceOver, display behavior, and complete update installation require the [manual validation checklist](manual-validation.md); offscreen caching does not fully capture native macOS glass.


## AltView sender

`LiveProjectionController` owns one `AltViewProjectionService` per configured remote destination, shared with its Manage Outputs editor. All services use one app-owned `AltViewDiscoveryService` inventory/browser/retry loop and the existing Keychain pairing store. Successful `publish` calls submit the prepared projection's `primaryText` and `primaryTranslationName` for Audience (including the existing secondary fallback for a missing primary verse). Confidence also carries the committed `secondaryText` and `secondaryTranslationName` when available, independent of the local projector's layout preferences. Blank submits the same text with `visible: false`; Stop releases every remote ownership request; closing a native destination leaves remote output running. No projection view, database reader, browsing completion, or individual tab owns a socket. Native teardown validates the destination instance; deferred committed-data cleanup validates the projection revision.

`AltView/` implements protocol v2 using Network.framework TLS-PSK, Bonjour discovery, a manual host/port endpoint, receiver UUID pinning, and Keychain storage. Transport/framing/discovery helpers were adapted from the sibling AltView implementation on 2026-10-02; the app has no build or runtime dependency on that checkout. Keychain operations run in their own actor. Existing data-protection items remain preferred; builds without its provisioning entitlements use the login Keychain with normal app-signature access control. Only missing entitlements permit a storage fallback; locked, denied, or corrupt entries report errors. No pairing secrets go into defaults. The shared discovery service runs while a receiver editor is visible or any enabled This Mac connection needs dynamic-port tracking, and retries failed discovery with capped backoff. Per-destination sessions retain independent setup, connection, ownership, acknowledgement and reconnect state. This Mac setup waits for fresh discovery of the saved receiver UUID before using a loopback port; a saved port cannot trigger a terminal failure against a different receiver. Connecting never claims output. AppDelegate requests restoration of enabled saved destinations once at launch; creating Settings or passage tabs never starts connections. Editing a destination or cancelling setup invalidates late callbacks, and cancellation lasts until manual connection or the next launch.

Every published snapshot includes the committed reference, primary verse/name and optional `secondary: {body, footer}` for the secondary verse/name in a separate Confidence object that survives Blank. Each secondary string uses the corresponding primary byte limit. Confidence data is sent intact without a separate secondary-translation capability or an older-receiver downgrade. Complete snapshots clear a missing secondary, and missing-primary fallback is never duplicated into two columns. The sender checks the complete escaped frame after resolving the requested template and again after welcome, before requesting ownership; rejected queued text cannot clear another sender's presentation. Settings preserves receiver menu items during routine status updates.

Connection attempts and backoff run on the sender's private queue, one socket and one scheduled retry at a time. Each setup attempt times out after 10 seconds; transient network failures retry indefinitely at 1, 2, 4, 8, 16, then 30-second intervals, resetting after a successful welcome. There is no heartbeat timer during backoff. Authentication, receiver-identity, and protocol failures stop retries and require intervention. Settings offers Cancel during setup/backoff and enables Disconnect only for an established connection. Startup restoration never claims output or republishes a previous projection.

`AltViewSenderClient` confines sockets, timers, leases, revisions, JSON work, and retries to its private queue. One mailbox per connection retains the latest complete submission and guards it by connection UUID. A separate publication intent changes only for explicit projection; translation refresh and blanking retain it and cannot create a takeover request. An explicit request remains pending until a fresh grant or acceptance of its snapshot revision (or a newer coalesced snapshot on that lease). A cached lease may already be revoked: the sender sends optimistically, then requests takeover when delayed ownership feedback invalidates the lease. Older acknowledgements cannot settle the request. An explicit projection made during reconnect, or a take interrupted before its grant arrives, retains the request through transient transport retries. Its latest snapshot is sent after the grant, without requiring the other app to release or a manual reconnect. Stop clears the pending request; during an ungranted take it closes that socket to cancel a late grant, then reconnects without ownership. Without a pending explicit take, established reconnect uses `resume` only for a former owner and never takes occupied output. The outbox bounds controls, snapshots, and heartbeats; text and escaped frame sizes are checked before ownership acquisition.

Template discovery follows the sibling AltView `docs/protocol.md` contract dated 2026-10-03. `welcome` and every `feedback` replace the full catalogue/policy; disconnect clears them. Opaque template IDs, unique bounded catalogues, and receiver policies are validated before use; invalid reports stop the connection. The sender retains desired content and resolves a copy against current capabilities immediately before every send, including hidden snapshots and reconnect restoration. Missing/null/empty catalogues omit the request; a supported request survives receiver overrides. Discovery updates never send snapshots or alter ownership/revisions.

The native advertised Layout menu uses receiver names for display and IDs for selection, including future IDs and repeated names. The output configuration persists each destination’s desired selection (Scripture by default; null means receiver layout); the service retains the current connection choice without its own defaults binding. Only an explicit projection commits it; Blank, automatic translation refresh, and reconnect keep the previously committed choice. Unavailable selections remain visible and recover if advertised again. The menu rebuilds only when entries or unavailable selection change, so routine feedback does not disrupt an open menu. Requested choice and applied receiver override are reported separately.

Tests use an isolated copy of AltView's receiver reducer/server, with injected delay/disconnect controls, to exercise real loopback TLS, stale-lease recovery and cancellation before delayed revocation, bursts, ownership, blank/release, cancellation, identity pinning, and recovery. Adapter tests inject the sender and pairing store and suppress physical projection. The Settings review renders the Manage Outputs receiver editor in light/dark with discovery disabled. Two-Mac Bonjour/Local Network consent, signed Keychain persistence, and physical output latency remain manual checks. Protocol v2 requires asynchronous `feedback` carrying receiver output readiness plus the owning connection’s latest accepted lease/revision. One replaceable feedback outbox slot bounds bursts. The sender tracks its latest sent and accepted revision, ignores stale leases and unsent/future revisions, and clears confirmation on release, takeover or disconnect. A five-second acknowledgement-progress timeout changes status only; it cannot gate sending, reconnect, or interfere with local projection. The adapter matches its current submission UUID before showing acceptance, including after Blank. This confirms receiver acceptance and software window availability, not frame rendering or physical HDMI output. Both apps must use v2; there is no negotiation or v1 fallback.


## Projection monitor and sleep ownership

The shared live controller owns `ProjectionDisplayManager` for inventory, remembered monitor labels, identity validation and per-destination active locks. Monitor assignments belong only to output destinations. The controller holds one `ProjectionSleepPrevention` activity whenever any actual native window is open, including Confidence standby, blanked and transparent outputs. Partial close/loss retains it; the last native close, shutdown or owner teardown releases it synchronously. Identify, browsing, preparation, preview and AltView connection alone never acquire it.

`OutputProfilesTests` cover versioned migration/recovery, component filtering and profile independence, monitor/receiver conflicts, full-frame hosting, partial teardown, clock rendering, sleep balance, remote-only publication and removal of competing editors. Existing passage regressions cover browsing/search/inactive-tab privacy, same-verse activation, source refresh and stale preparation. The encrypted Manage Outputs test drives pairing through its native editor, restores the saved receiver, verifies Connect Only, Blank, passive refresh, reconnect, takeover and Stop. Physical monitors, Spaces, Dock/menu-bar coverage, Local Network consent and signed Keychain persistence remain manual checks.
